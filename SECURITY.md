# Security policy

## Scope

This repository holds experiments with GitHub Actions workflows, repository settings and rulesets, issue and pull request flows, and releases. It ships no software for use.

## What to report privately

- A secret, a credential or personal data committed to this repository by mistake, in a file or in the history.
- A weakness of the workflows under `.github/` that could let someone change what the repository runs or publishes.

## How to report

Use GitHub's private vulnerability reporting (the tab Security, then Report a vulnerability), or write to [info@mtorun0x7cd.com](mailto:info@mtorun0x7cd.com), naming the file, the problem and how to see it. Do not open a public issue for it.

## What is not a vulnerability

A workflow that does what its file says is not a vulnerability, and neither is a check that fails on purpose during an experiment. A pinned version that is not the newest one is not a vulnerability either.

## What to expect

Reports are read. A reply or a fix is not guaranteed.
